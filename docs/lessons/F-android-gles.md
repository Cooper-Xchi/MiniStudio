# F 阶段：Android 与 OpenGL ES

## 阶段前置与共同边界

桌面 OpenGL 渲染器及 E 阶段基线已经稳定。准备至少一台可调试 Android 真机；没有真机时可完成环境和模拟器练习，但不能把移动端阶段标为已验收。

先迁移一个纹理模型及固定光照的最小场景，再按能力恢复其他效果。记录 Android 生命周期线程、渲染线程与 EGL current context 归属；桌面 GlfwWindow 不承担 Android 适配。NDK、SDK、构建插件和分析工具在开课时检查官方兼容要求，安装和新依赖遵守确认规则。

课内按顺序推进，后课以前课的验收成果为前置；每课只完成下列一个核心练习。若环境准备或实现超过 90 分钟，拆课并更新实际课号，不省略验收。所有实现课都须实际读改动并完成与风险相称的构建／运行检查；复盘课如改代码，也须补做行为回归。

## 第一组：Android 工程与生命周期

### F01：设备与工具链准备方案

- **用时**：30～60 分钟。
- **讲解**：SDK／NDK、ABI、设备 API 级别、调试与发布包。
- **核心练习与边界**：核对现有设备和开发主机，列出最小工具链及安装成本后等确认。
- **验收**：能说明设备与构建产物的匹配关系，没有将模拟器当成真机性能证据。

### F02：最小 native 工程

- **用时**：60～90 分钟。
- **讲解**：Android 构建入口、CMake 目标、动态库与日志。
- **核心练习与边界**：在工具链已就绪条件下运行一个最小 C++ 日志程序。
- **验收**：真机能启动、退出并看到 native 日志，记录 ABI 与构建配置。

### F03：生命周期事件观察

- **用时**：45～75 分钟。
- **讲解**：创建、可见、前后台、Surface 事件和回调线程。
- **核心练习与边界**：只记录启动、切后台、返回和退出事件及线程 ID，不接渲染器。
- **验收**：实测顺序有记录，能说明回调顺序和线程不能凭桌面经验猜测。

### F04：平台层职责复盘

- **用时**：30～50 分钟。
- **讲解**：应用壳、事件桥接、渲染线程和资源模块的边界。
- **核心练习与边界**：根据 F03 实测写线程／所有权图，确定最小 Android 窗口边界。
- **验收**：桌面入口继续独立，公共资源模块没有包含 Android 应用对象。

## 第二组：EGL 与第一条绘制路径

### F05：Surface 与 EGL Context

- **用时**：60～90 分钟。
- **讲解**：显示、配置、Surface、Context 与 current 绑定。
- **核心练习与边界**：在已选应用壳中建立最小 EGL 生命周期，先只清理和报告错误。
- **验收**：成功与失败路径均释放已创建对象，Context 所在线程可解释。

### F06：OpenGL ES 清屏与呈现

- **用时**：45～75 分钟。
- **讲解**：EGL 呈现、绘制循环、可绘制表面条件。
- **核心练习与边界**：在 F05 基础上清屏呈现一帧，再接最小连续循环。
- **验收**：屏幕颜色正确，无 Surface 时不继续无效绘制，退出顺序正确。

### F07：Shader 方言与能力差异

- **用时**：50～80 分钟。
- **讲解**：GLSL ES 版本、精度、桌面功能依赖与错误日志。
- **核心练习与边界**：将一个最小 Shader 移到 ES 目标，先显示常量颜色三角形。
- **验收**：编译／链接错误完整，支持版本取自实际设备；不盲目替换版本字符串。

### F08：上下文与绘制边界复盘

- **用时**：30～50 分钟。
- **讲解**：平台呈现与图形资源调用、初始化失败传播。
- **核心练习与边界**：复核 EGL 与渲染资源的销毁依赖，列出现阶段桌面／移动差异。
- **验收**：底层网格和图片数据仍可复用，未提前设计通用 RenderDevice。

## 第三组：迁移最小场景

### F09：网格缓冲迁移

- **用时**：50～80 分钟。
- **讲解**：顶点／索引类型、布局与 API 支持检查。
- **核心练习与边界**：将已有立方体 MeshData 接到 ES 上传与索引绘制路径。
- **验收**：几何与绕序正确，支持限制有提示，没有把格式解析复制进移动渲染器。

### F10：纹理上传迁移

- **用时**：50～80 分钟。
- **讲解**：像素布局、纹理格式、过滤和资源路径差异。
- **核心练习与边界**：复用 CPU 图片解码，上传一张受控纹理到真机。
- **验收**：非对称图方向正确，缺资源可诊断，GPU 上传留在 current 线程。

### F11：矩阵与深度场景对照

- **用时**：50～80 分钟。
- **讲解**：投影宽高比、深度状态与平台输出对照。
- **核心练习与边界**：迁移桌面的纹理立方体和一个受控遮挡实验。
- **验收**：两个平台几何与遮挡语义一致，差异有具体记录而非要求像素完全一致。

### F12：移植资源架构复盘

- **用时**：30～50 分钟。
- **讲解**：可共享 CPU 代码、平台状态和资源重建输入。
- **核心练习与边界**：标记当前可共享／需适配文件与原因，检查双平台构建边界。
- **验收**：修改移动目标不破坏桌面配置，共享模块没有双向依赖。

## 第四组：输入、尺寸与前后台

### F13：触摸意图桥接

- **用时**：50～80 分钟。
- **讲解**：触点 ID、坐标单位、移动／抬起／取消事件。
- **核心练习与边界**：把单指拖动转换为既有相机观察意图；不做复杂多指手势。
- **验收**：拖动方向一致，取消和抬起后停止，Camera 不调用平台输入 API。

### F14：旋转与实际渲染尺寸

- **用时**：50～80 分钟。
- **讲解**：Surface 尺寸、显示密度、方向变化与 viewport。
- **核心练习与边界**：横竖屏切换时同步目标尺寸和 projection，处理零尺寸窗口期。
- **验收**：模型不拉伸，短暂无表面不报错，触摸坐标映射有说明。

### F15：后台暂停与恢复

- **用时**：50～80 分钟。
- **讲解**：可见性、渲染许可、时钟断点与节能。
- **核心练习与边界**：进入后台暂停不必要绘制，回来重置合适的帧时间基准。
- **验收**：后台不持续空转，返回无巨大相机跳变，日志证明状态转换。

### F16：输入与生命周期复盘

- **用时**：30～50 分钟。
- **讲解**：平台事件到渲染线程的传递、共享状态同步。
- **核心练习与边界**：用切后台／旋转序列画时序，检查无锁共享标志和队列寿命。
- **验收**：每项跨线程状态有同步约束，Surface 失效后无继续提交。

## 第五组：Context 丢失与资源恢复

### F17：Context 失效识别

- **用时**：45～75 分钟。
- **讲解**：Surface 重建与 Context 丢失的不同含义、错误分类。
- **核心练习与边界**：增加可控销毁／重建实验入口，记录失效与停止绘制状态。
- **验收**：不假定切后台必定丢 Context；真实事件和人工注入分别标注。

### F18：从 CPU 描述重建 GPU 资源

- **用时**：60～90 分钟。
- **讲解**：失效句柄、重建顺序、保留 CPU 数据与重新加载的取舍。
- **核心练习与边界**：在新 Context 内重建最小场景的网格和纹理，旧句柄不再使用。
- **验收**：受控重建后恢复正确画面，资源计数和所有权可解释。

### F19：恢复期间取消旧任务

- **用时**：50～80 分钟。
- **讲解**：Context 代次、异步完成结果和发布有效性。
- **核心练习与边界**：将旧 Context 的待上传任务判为过期，再发起当前代次加载。
- **验收**：晚到结果不会上传到错误状态，恢复与退出交错时可安全结束。

### F20：移动资源寿命复盘

- **用时**：30～50 分钟。
- **讲解**：应用、Surface、Context、CPU 资源和 GPU 资源的不同寿命。
- **核心练习与边界**：绘制五层生命周期，记录重建所需输入和释放责任。
- **验收**：不能用“程序还在运行”推断 GPU 句柄仍有效，失败恢复链路完整。

## 第六组：能力与预算

### F21：设备能力表与降级选择

- **用时**：45～75 分钟。
- **讲解**：能力查询、限制、扩展和效果支持矩阵。
- **核心练习与边界**：对当前场景列出必要能力，缺失时选择一个明确默认路径。
- **验收**：真机能力有实测值，不支持功能能降级或报告而非黑屏。

### F22：纹理尺寸与内存预算

- **用时**：50～80 分钟。
- **讲解**：像素数量、Mipmap 成本、压缩支持和质量取舍。
- **核心练习与边界**：对一张过大素材实施一种受控尺寸策略；压缩格式先只评估。
- **验收**：记录内存估算与视觉对照，超出尺寸限制前可检测。

### F23：移动加载预算

- **用时**：50～80 分钟。
- **讲解**：上传尖峰、内存峰值、后台工作与响应性。
- **核心练习与边界**：用既有队列调小在途／上传预算，测一次真机加载过程。
- **验收**：时间与峰值同时记录，等待中界面仍可操作，没有无限排队。

### F24：移动降级架构复盘

- **用时**：30～50 分钟。
- **讲解**：能力数据、策略决策与底层执行的职责。
- **核心练习与边界**：记录一个效果降级决策经过哪些模块，检查平台判断是否散落。
- **验收**：资源加载不自行决定产品效果，平台条件集中在明确边界。

## 第七组：真机测量

### F25：真机性能基线

- **用时**：45～75 分钟。
- **讲解**：帧时间、分辨率、温度、充电和持续运行条件。
- **核心练习与边界**：用固定相机路径采集一轮真机基线，注明采样时长与设备状态。
- **验收**：有原始样本与环境，短时结果不被表述为长期热稳定性。

### F26：移动 GPU／CPU 定位

- **用时**：50～80 分钟。
- **讲解**：平台分析工具、提交与执行、热降频和测量干扰。
- **核心练习与边界**：用当时设备支持的工具验证一个瓶颈假设。
- **验收**：工具限制和证据明确；无法采集的指标写缺失，不捏造功耗数字。

### F27：一项移动优化实验

- **用时**：50～80 分钟。
- **讲解**：分辨率、绘制／采样成本与画质、响应性的权衡。
- **核心练习与边界**：针对 F26 的证据只改一个变量，比较同条件数据。
- **验收**：收益与画质代价都记录；无收益则回退或保留原方案并解释。

### F28：移动性能架构复盘

- **用时**：30～50 分钟。
- **讲解**：设备差异、可配置质量与硬编码特例的维护成本。
- **核心练习与边界**：汇总测量结论并审查新增设备判断是否必要。
- **验收**：结论限定在实测设备与场景，未把一台手机推断成全部 Android。

## 第八组：兼容性与交付

### F29：移动故障记录

- **用时**：45～75 分钟。
- **讲解**：设备信息、上下文状态、资源 ID、错误日志与敏感信息。
- **核心练习与边界**：为一次已有恢复失败或素材失败生成最小诊断记录。
- **验收**：记录足以重现且不包含凭据，普通用户可看到可操作的错误提示。

### F30：设备与操作矩阵

- **用时**：40～70 分钟。
- **讲解**：平台覆盖、未测试项、生命周期组合和风险排序。
- **核心练习与边界**：回归至少一台真机的启动／旋转／后台／恢复／退出，整理矩阵。
- **验收**：每格明确通过／失败／未测；模拟器和桌面证据分开。

### F31：可安装预览器与说明

- **用时**：45～75 分钟。
- **讲解**：调试构建、资源打包、运行步骤和设备约束。
- **核心练习与边界**：打包已完成场景并写安装运行说明，保留桌面对照入口。
- **验收**：指定设备可安装运行，包不含凭据，未授权时不发布应用商店。

### F32：移动阶段验收与季度复盘

- **用时**：45～75 分钟。
- **讲解**：双平台行为、真机性能和生命周期证据的完整性。
- **核心练习与边界**：审查兼容矩阵、重建实验与一项实测优化，选 Vulkan 核心场景。
- **验收**：macOS 与至少一台 Android 各有实际证据；缺平台验证则补验后再过阶段。
