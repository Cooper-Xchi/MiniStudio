## 每一课共同执行的流程

1. **开课前**：核对上一课验收与合并状态、最新稳定 `main`、工作区改动以及实际运行平台；只读检查目录、职责、所有权和依赖。满足仓库规则后创建本课分支。
2. **先讲再做**：说明目标、为什么需要、陌生 C++ 语法、CPU/GPU 数据流与本课边界。给接口、伪代码、局部示例和观察点，由学习者完成核心练习。
3. **资源约定**：新增有状态对象时先写主要职责、最小接口、所有者、销毁时机、复制／移动规则和运行线程；无状态算法不强行包装成类。
4. **当课验收**：实际读代码；按风险配置、编译、运行或做故障实验。除画面外，至少回答一个“为什么”；失败先定位，不用整体重写代替理解。
5. **保留证据**：记录修改文件、构建配置、实际平台、场景、预期／实测、错误与修复、遗留问题。macOS、Windows、Android 的结果各自记录；未运行的平台写“未验证”。
6. **结束后**：更新交接状态。提交、推送和合并按学习者的明确授权执行；教案不预先授权这些操作。

文档复盘课通常提交一页职责／依赖／所有权记录及一个可复现问题分析，不要求为了复盘强行重构。确有职责混杂时，将最小重构作为当课核心任务，并重新验证行为。
