# K 阶段：规模化性能与架构演进

[返回逐课索引](README.md) · 第 31～33 月／第 131～143 周

> 状态：全部为待执行教案，开课时依据实际进度和工具支持复核。

## 阶段前置与共同边界

已有性能基线、资源句柄、异步取消与至少两条稳定后端路径。选择一个真正暴露容量问题的目标场景和一台主要测量设备，不凭空追求百万对象或全平台同规模。

每项优化必须保留 E 阶段的测量方法。本阶段允许按真实需求引入空间索引、流式策略或帧分配方案，但每课只验证一个切片。后台线程默认准备 CPU 数据；录制 GPU 命令需按具体后端的线程与资源规则另行验证。Filament／Skia 只选相关模块阅读，不复制整套架构。

课内按顺序推进，后课以前课的验收成果为前置；每课只完成下列一个核心练习。若环境准备或实现超过 90 分钟，拆课并更新实际课号，不省略验收。所有实现课都须实际读改动并完成与风险相称的构建／运行检查；复盘课如改代码，也须补做行为回归。

## 第一组：预算与压力问题

### K01：规模目标与负载模型

- **用时**：35～60 分钟。
- **讲解**：对象数、资源体积、可见比例、到达速率与用户操作。
- **核心练习与边界**：根据已有痛点定义一个可重放大场景及成功／失败阈值。
- **验收**：指标对应实际设备预算，不用仅能截图的静态极限作为目标。

### K02：资源成本与预算分类

- **用时**：45～75 分钟。
- **讲解**：常驻／可淘汰／在途资源、CPU 与 GPU 预算和估算误差。
- **核心练习与边界**：为一类资源补成本字段，汇总当前场景预算占用。
- **验收**：能追踪一份资源的成本来源，未知 GPU 实际占用明确标估算。

### K03：队列反压与请求上限

- **用时**：50～80 分钟。
- **讲解**：生产消费速率、排队延迟、拒绝／降级与优先级。
- **核心练习与边界**：给现有加载入口加一条有界接收策略，并测过载行为。
- **验收**：队列不无限增长，拒绝可见，正常负载仍响应且不会饥饿。

### K04：预算架构复盘

- **用时**：30～50 分钟。
- **讲解**：策略决策、资源成本、任务执行和统计的责任。
- **核心练习与边界**：画预算检查到任务接收的路径，检查锁内工作和重复统计。
- **验收**：资源模块不直接决定 UI 体验，容量不变量可独立验证。

## 第二组：流式加载与淘汰

### K05：相机相关加载优先级

- **用时**：50～80 分钟。
- **讲解**：可见／即将可见需求、距离、优先队列与饥饿。
- **核心练习与边界**：对既有分块场景实现一种简单优先级，先保持资源格式不变。
- **验收**：相机移动时关键资源更早可用，低优先请求有明确处理。

### K06：最小资源淘汰策略

- **用时**：60～90 分钟。
- **讲解**：LRU 或代价策略、正在使用／在途引用与安全释放。
- **核心练习与边界**：对一类可重载资源实施有预算的淘汰，不同时支持多种策略。
- **验收**：预算恢复、活跃资源不被误释放，GPU 在途资源延迟回收条件明确。

### K07：快速移动与请求去重

- **用时**：50～80 分钟。
- **讲解**：取消、需求版本、重复请求与回头重载的代价。
- **核心练习与边界**：重放快速往返相机路径，合并重复请求并丢弃过期结果。
- **验收**：无旧结果覆盖新需求，记录缓存命中与浪费上传，不出现持续抖动加载。

### K08：流式资源架构复盘

- **用时**：35～60 分钟。
- **讲解**：需求集、加载任务、资源缓存、发布与回收之间的契约。
- **核心练习与边界**：用一个资源从需要到淘汰的时间线检查句柄和代次。
- **验收**：每个状态都有退出路径，预算策略不依赖具体 GPU 句柄类型。

## 第三组：空间与可见性扩展

### K09：空间索引的必要性实验

- **用时**：45～75 分钟。
- **讲解**：线性遍历、层级索引、查询与维护的复杂度。
- **核心练习与边界**：对固定静态场景比较现有遍历与一种简单空间划分的候选数量。
- **验收**：记录维护成本与适用规模，收益不足时不把复杂结构接入主线。

### K10：受控 LOD 选择

- **用时**：50～80 分钟。
- **讲解**：屏幕误差、距离阈值、切换滞回与资源依赖。
- **核心练习与边界**：为一个有现成多精度版本的模型实现简单 LOD，不自研简化算法。
- **验收**：切换稳定且资源可用，画质／时间／内存都有对照。

### K11：大场景批次准备

- **用时**：50～80 分钟。
- **讲解**：可见集、材质／网格分组、实例容量与透明限制。
- **核心练习与边界**：对选定不透明场景扩展已有实例批次，测准备和提交成本。
- **验收**：无误剔除或透明顺序破坏，缓冲容量与拆批规则明确。

### K12：空间与批次架构复盘

- **用时**：30～50 分钟。
- **讲解**：静态索引、动态实例、相机查询和 GPU 提交的分工。
- **核心练习与边界**：检查变换修改如何更新索引／包围体，记录失效条件。
- **验收**：空间结构不拥有可变渲染状态，新增结构有真实测量依据。

## 第四组：多线程准备与帧资源

### K13：并行 CPU 绘制准备

- **用时**：60～90 分钟。
- **讲解**：不可变场景快照、分片工作、汇合与确定性合并。
- **核心练习与边界**：只把一个 CPU 准备阶段放入已有任务系统，主线程仍提交绘制。
- **验收**：与串行结果一致，读写集合明确，性能包含调度和汇合成本。

### K14：帧临时数据预算

- **用时**：50～80 分钟。
- **讲解**：帧数据寿命、容量复用、分配次数与跨帧引用。
- **核心练习与边界**：依据分配数据复用一个帧临时容器；无必要不自研分配器。
- **验收**：分配峰值降低或结论明确，上一帧指针不在复用后被继续使用。

### K15：GPU 帧任务与完成条件

- **用时**：60～90 分钟。
- **讲解**：CPU 工作完成、GPU 提交、执行完成和资源退休。
- **核心练习与边界**：对一个现有后端把帧资源回收与明确完成点关联，保持范围可测。
- **验收**：高负载下不提前回收，等待减少须有数据；不跨所有后端一次改写。

### K16：并行与帧调度复盘

- **用时**：35～60 分钟。
- **讲解**：任务依赖、锁、提交线程与在途数据所有权。
- **核心练习与边界**：绘制 CPU／GPU 帧时间线，审查嵌套等待和完成回调。
- **验收**：可解释每个等待的用途，没有依赖 sleep 的同步或隐含跨帧借用。

## 第五组：诊断基础

### K17：有界帧诊断记录

- **用时**：50～80 分钟。
- **讲解**：环形缓冲、事件 ID、时间范围和诊断开销。
- **核心练习与边界**：为一次卡顿保留前后有限帧的关键事件，不逐帧无限写盘。
- **验收**：可关联帧与资源任务，内存有上限，关闭记录不影响业务结果。

### K18：卡住与等待定位

- **用时**：45～75 分钟。
- **讲解**：调用栈、锁等待、线程状态与 GPU 等待的区分。
- **核心练习与边界**：在受控实验中复现一个等待问题，用栈和时间线缩小原因。
- **验收**：能指出等待对象及持有者，不把所有卡顿都归为 GPU 慢。

### K19：崩溃与符号信息

- **用时**：45～75 分钟。
- **讲解**：构建标识、符号化、最小上下文与隐私边界。
- **核心练习与边界**：对已有受控故障保存可定位栈和版本信息，按实际平台工具验证。
- **验收**：报告能对应源码版本，诊断包不包含凭据或无关用户素材。

### K20：诊断所有权与架构复盘

- **用时**：30～50 分钟。
- **讲解**：事件生产、缓存、导出与故障时可用性的边界。
- **核心练习与边界**：检查崩溃／退出时记录对象的寿命和阻塞风险。
- **验收**：诊断不会依赖已销毁 UI 或无限等待工作线程，不建设全能日志框架。

## 第六组：端到端追踪与压力

### K21：素材任务关联追踪

- **用时**：50～80 分钟。
- **讲解**：请求 ID、父子任务、资源版本和跨线程时间线。
- **核心练习与边界**：将一次流式素材请求的读取／解码／上传／可见事件关联起来。
- **验收**：可解释等待发生在哪一段，不把多个请求的日志误拼成一条。

### K22：素材失败诊断包

- **用时**：45～75 分钟。
- **讲解**：可重现输入描述、支持范围、错误阶段与最小证据。
- **核心练习与边界**：为一个损坏素材生成有限诊断包，保留摘要与必要元信息。
- **验收**：不复制无关素材和凭据，能从报告定位解析还是上传失败。

### K23：组合压力回归

- **用时**：50～80 分钟。
- **讲解**：大场景、快速移动、取消、重载与退出的交错。
- **核心练习与边界**：重放一条有种子的组合序列，记录失败与预算峰值。
- **验收**：可复现且有停止条件，失败缩减为最小序列后再修复。

### K24：稳定性与规模复盘

- **用时**：35～60 分钟。
- **讲解**：容量、失败恢复、可观测性和维护复杂度的联合评估。
- **核心练习与边界**：归档本轮数据并列出最值得重构的一个边界问题。
- **验收**：选择来自真实缺陷或成本，不为了阅读大引擎而先全盘重构。

## 第七组：源码对照与设计提案

### K25：选择一个成熟项目模块

- **用时**：35～60 分钟。
- **讲解**：Filament／Skia 的领域、阅读入口和版本可追溯性。
- **核心练习与边界**：按 K24 问题只选一个相关资源／材质／2D 模块，固定源码版本和阅读问题。
- **验收**：有具体问题与文件入口，不把整个项目列成一节源码阅读任务。

### K26：所有权与依赖源码导读

- **用时**：50～80 分钟。
- **讲解**：构造、调用入口、资源持有、错误传播与销毁。
- **核心练习与边界**：追踪所选模块的一条完整路径，对照 MiniStudio 的同一责任。
- **验收**：记录具体源码位置、相似点和条件差异，不直接照抄不适用架构。

### K27：最小架构升级提案

- **用时**：50～80 分钟。
- **讲解**：现状问题、约束、方案、替代方案与迁移成本。
- **核心练习与边界**：为 K24 的问题写一份可审阅提案，只选择一个模块切片。
- **验收**：有可衡量目标、影响范围、兼容策略和回滚条件，尚不大面积改代码。

### K28：提案与依赖复盘

- **用时**：35～60 分钟。
- **讲解**：不变量、公开接口、测试证据和失败时旧路径。
- **核心练习与边界**：用成功／失败调用样例检查提案，确认所需真实依赖。
- **验收**：不增加循环依赖或万能管理器，复杂度与收益可以说明。

## 第八组：迁移与回滚证据

### K29：实现一个迁移切片

- **用时**：60～90 分钟。
- **讲解**：渐进替换、适配入口、旧新结果对照与变更边界。
- **核心练习与边界**：按已确认提案迁移一个可独立运行的路径；余下切片另拆课。
- **验收**：新路径通过同输入对照，旧路径仍可运行，未完成范围有清单。

### K30：兼容旧数据或调用方

- **用时**：50～80 分钟。
- **讲解**：格式／接口兼容、转换边界与过渡代码寿命。
- **核心练习与边界**：对 K29 的切片补一个必要兼容路径，验证旧样本。
- **验收**：旧输入语义不丢失，过渡代码有退出条件，不永久保留多套无主实现。

### K31：受控回滚演练

- **用时**：45～75 分钟。
- **讲解**：回滚触发条件、资源／数据恢复与验证顺序。
- **核心练习与边界**：在测试副本或受控配置中切回旧路径，保留新数据的恢复办法。
- **验收**：可恢复原行为，不用强制推送或破坏性重置代替系统回滚策略。

### K32：规模化阶段验收与季度复盘

- **用时**：50～80 分钟。
- **讲解**：测量、源码取舍、渐进迁移和故障恢复的证据。
- **核心练习与边界**：汇总预算报告、诊断样本、提案及已完成迁移／回滚结果。
- **验收**：有一个真正完成且可回滚的切片；剩余范围补课，成果尽量映射真实协作责任。
