## 第 10 周：从平面走向立体

### 第 37 课：三角形绕序与正面判定

- **实际状态（2026-09-09）**：已验收，待提交合并；macOS Debug 构建与运行检查通过，Windows 尚未验证本课。详细证据见交接文档，以下保留原教案。
- **用时／前置**：35～60 分钟；第 36 课已合并，当前主机稳定基线可构建运行。
- **目标与讲解**：认识顺时针／逆时针绕序、索引顺序、正面约定；区分正反面判定与深度比较。解释项目枚举如何隔离 OpenGL 常量。
- **练习步骤**：先画出当前两个三角形的索引方向；在现有无状态命令边界增加最小正面约定接口；保持剔除关闭，在片元 Shader 用正反面标记显示两种颜色；只交换一个三角形的绕序观察，再恢复。
- **边界**：只研究正反面，不加入剔除、法线、光照或新资源类；Renderer 编排，RenderCommand 执行状态调用。
- **验收**：改变正面约定及交换绕序能得到可解释的颜色变化，恢复后两个三角形方向一致；构建与 Shader／OpenGL 错误检查通过。
- **易错／追问**：不要把“朝向相机”简单等同于“离相机更近”。只调整索引顺序，深度值必然改变吗？

### 第 38 课：背面剔除与双面表面

- **用时／前置**：35～60 分钟；第 37 课的绕序实验完成。
- **目标与讲解**：认识剔除开关、剔除哪一面与正面约定的独立职责；理解平面转到背面后消失的原因。
- **练习步骤**：在原命令模块增加最小剔除控制；固定正面约定，让矩形绕 Y 轴转动；比较关闭剔除、剔除背面、剔除正面三组结果；保存统一默认状态。
- **边界**：不为了三个状态设计通用渲染状态系统；保持清屏与深度状态顺序正确。
- **验收**：逐组记录可见面，能区分绕序错误、剔除错误和深度错误；恢复正常配置后无 OpenGL 错误。
- **易错／追问**：矩形突然不可见时先查面朝向，而不是立即改 near／far。为什么树叶一类平面素材可能需要双面显示？

### 第 39 课：索引立方体与面独立 UV

- **用时／前置**：60～90 分钟；第 38 课验收，现有顶点布局与 EBO 链路稳定。
- **目标与讲解**：把立方体拆成六面，理解几何位置相同但 UV 不同的顶点需要不同属性记录；复习数组、索引范围与 stride。
- **练习步骤**：先只读检查固定矩形数据的位置，决定最小 CPU 几何数据边界；参考一面的局部示例补出六面、各面 UV 和一致绕序；使用现有 GPU 资源上传，绕两个轴观察。
- **边界**：只做一个立方体，不实现通用 Mesh 管理、模型导入或法线光照；CPU 几何生成可用普通函数，GPU 句柄仍由现有 RAII 对象独占。
- **验收**：六面纹理方向可逐面解释，索引不越界，背面剔除与深度测试下遮挡正确；构建、运行和资源退出检查通过。
- **易错／追问**：用八个角点强行共享所有 UV 会出现什么问题？为什么索引引用的是完整属性记录？

### 第 40 课：几何、状态与资源架构复盘

- **用时／前置**：30～50 分钟；第 37～39 课完成。
- **目标与讲解**：梳理 CPU 顶点／索引、GPU 缓冲、逐帧 model、剔除与深度状态的不同生命周期。
- **练习步骤**：绘制当前依赖和销毁顺序；写清几何数据生成、上传、绘制分别放在哪里；用一个“索引绕序错误”的排查顺序检验边界。
- **边界**：核心产物是一页复盘；只有发现职责混杂才安排最小拆分，不提前提取 RenderDevice。
- **验收**：每个资源都能指出唯一所有者和释放时机；main 未增加绘图细节；如有重构，前后画面与退出行为一致。
- **易错／追问**：VAO 记录布局是否意味着它拥有 CPU 顶点数组？

## 第 11 周：相机与按键移动

### 第 41 课：Camera 的最小职责与静态 view

- **用时／前置**：45～75 分钟；第 40 课复盘完成。
- **目标与讲解**：把相机位置、朝向和 view 计算从 Renderer 的场景常量中分离；学习纯 CPU 状态与 GPU 资源的不同复制规则。
- **练习步骤**：先写 Camera 的职责和接口草案，例如读取 view、设置位置；确定由高层场景／Application 按值拥有，Renderer 只借用计算结果；迁移当前静态相机并保持画面一致。
- **边界**：Camera 不依赖 GLFW/OpenGL，不轮询输入、不拥有 GPU 句柄；本课暂不实现鼠标和移动。
- **验收**：静态画面与迁移前一致；头文件依赖单向；能说明 Camera 与 Renderer 分别保存什么，谁负责逐帧上传。
- **易错／追问**：为什么“相机改变 view”和“Shader 上传 view”不应成为同一个职责？

### 第 42 课：帧间时间与移动积分

- **用时／前置**：35～60 分钟；第 41 课完成。
- **目标与讲解**：区分累计时间和本帧间隔，理解速度乘时间得到位移；解释单调时钟、秒单位与首次采样。
- **练习步骤**：Application 保留上一帧时间，生成帧间秒数；先让 Camera 沿一条固定轴匀速移动；用几组人工时间步做不超过 30 行的小实验，再接回实际时钟。
- **边界**：仍保留累计时间给物体旋转；不加入固定步物理系统。调试暂停后是否限制时间步要显式记录，不能悄悄混用两种时间语义。
- **验收**：两组总时长相同的时间步得到相同位移（允许浮点误差）；实际运行速度合理，第一帧没有异常跳跃。
- **易错／追问**：每帧固定移动 0.01，与每秒移动 1 的区别如何通过实验看出来？

### 第 43 课：输入快照驱动相机平移

- **用时／前置**：50～80 分钟；第 42 课的时间步正确。
- **目标与讲解**：区分平台按键状态与应用移动意图；认识值传递的输入快照、只读借用与坐标轴选择。
- **练习步骤**：由窗口侧提供最小的前后左右按键快照，不暴露 GLFWwindow；Application 将移动意图和 delta time 交给 Camera；先保持固定朝向，实现按住移动、松开停止。
- **边界**：不建通用事件总线或全局 Input Manager；不在 Camera 内调用 GLFW；斜向速度问题留到第 47 课。
- **验收**：单方向按键和相反方向组合符合预期，松开停止，Esc 原行为仍正常；能从平台输入追踪到 view 更新。
- **易错／追问**：为什么按键状态应在本帧事件处理后读取？引用输入快照能否保存到下一帧使用？

### 第 44 课：时间、输入和相机依赖复盘

- **用时／前置**：30～50 分钟；第 41～43 课完成。
- **目标与讲解**：区分事件采集、意图生成、相机状态推进、矩阵上传与呈现；检查 Camera 的接口与复制规则。
- **练习步骤**：画出一帧五个步骤和数据箭头；给每项数据标记所有者、单位、生命周期与线程；复现一次按键更新顺序错误并解释。
- **边界**：不把输入搬到后台线程；文档课不要求新增框架。
- **验收**：Camera 仍可脱离窗口用固定输入测试；窗口底层没有反向依赖 Camera／Renderer；重构时补做运行回归。
- **易错／追问**：为什么测试 Camera 位移不必创建 OpenGL Context？

## 第 12 周：鼠标观察与移动体验

### 第 45 课：鼠标位移与焦点切换

- **用时／前置**：45～75 分钟；第 44 课完成。
- **目标与讲解**：认识绝对光标位置、相邻采样差值、首帧基准和输入捕获的生命周期。
- **练习步骤**：在窗口输入边界收集本帧鼠标位移；先打印受控样本而不改变相机；增加进入／退出捕获的操作，并在重新获焦或捕获时重置采样基准。
- **边界**：只完成可靠输入，不顺带写旋转算法；保留用户可退出捕获和关闭窗口的路径。
- **验收**：静止时位移接近零；第一次采样和切回窗口不会产生巨大跳变；切出后不继续使用旧输入。
- **易错／追问**：把旧位置初始化为屏幕原点为什么可能导致第一帧猛转？

### 第 46 课：yaw／pitch 驱动观察方向

- **用时／前置**：60～90 分钟；第 45 课输入稳定。
- **目标与讲解**：认识偏航、俯仰、角度／弧度、方向向量和正交基；解释限制极端俯仰的用途。
- **练习步骤**：先用几个固定角度验证前向向量，再把鼠标位移乘灵敏度更新 Camera 的 yaw／pitch；从方向生成 view，并统一上方向约定。
- **边界**：本课做自由观察的最小实现，不进入四元数或相机动画；鼠标位移的单位与按键速度不同，是否乘 delta time 必须按输入语义解释。
- **验收**：左右／上下观察符合约定，长时间旋转没有明显基向量漂移，极端俯仰不会翻转或出现非法矩阵。
- **易错／追问**：把“本帧已经累计的像素位移”再乘时间，会怎样影响灵敏度？

### 第 47 课：相机局部移动与斜向归一化

- **用时／前置**：40～65 分钟；第 46 课方向计算正确。
- **目标与讲解**：理解世界轴与相机局部轴、向量长度、单位方向和零向量边界。
- **练习步骤**：用相机前向／右向组合按键意图；明确采用自由飞行还是水平移动，本阶段默认自由飞行；仅在非零时归一化合成方向，再按速度与时间更新位置。
- **边界**：只解决方向与速度一致性；不增加碰撞、加速度或角色控制器。
- **验收**：相同总时间内直行与斜行距离接近；转头后前进方向跟随相机；相反按键抵消且不会产生 NaN。
- **易错／追问**：为什么不能对所有输入无条件调用归一化？

### 第 48 课：交互相机回归与架构复盘

- **用时／前置**：35～60 分钟；第 45～47 课完成。
- **目标与讲解**：把输入焦点、时间、相机状态、窗口尺寸和 GPU 生命周期放在同一条运行路径中审查。
- **练习步骤**：列出移动、转头、失焦／获焦、resize、最小化／恢复、关闭六类操作；执行可用平台上的回归，记录不支持或未验证的操作；复核职责图。
- **边界**：核心任务是集成回归，不顺便实现多种相机或输入绑定系统。
- **验收**：可复现测试表有实测结果；无卡键、首帧猛转或零尺寸错误；Camera 不拥有平台或 GPU 资源。
- **易错／追问**：失焦和最小化是同一种状态吗？为什么测试时要分开记录？

## 第 13 周：透明基础与 v0.2 验收

### 第 49 课：Alpha 裁剪与带孔平面

- **用时／前置**：40～65 分钟；第 48 课通过。
- **目标与讲解**：认识纹理 alpha、阈值裁剪与片元丢弃；结合深度测试理解“透明孔仍挡住后方”的排查方向。
- **练习步骤**：使用程序生成的中心带孔 RGBA 小图，避免新增图片依赖；在现有片元 Shader 加阈值裁剪；用孔后方的立方体验证，并按表面需求选择双面显示。
- **边界**：只处理全保留／全丢弃，不做半透明或抗锯齿扩展；最终恢复明确的剔除默认状态。
- **验收**：孔中可见后方物体，实心区域正常遮挡；能区分 alpha 为零和实际丢弃片元的不同结果。
- **易错／追问**：只让颜色 alpha 为零、既不裁剪也未配置混合，为什么不能据此判断孔已经正确实现？

### 第 50 课：颜色混合与一个半透明表面

- **用时／前置**：45～75 分钟；第 49 课完成。
- **目标与讲解**：区分源颜色、目标颜色、混合因子及深度状态；本课明确使用非预乘 alpha 约定。
- **练习步骤**：先手算一个前景／背景颜色组合；增加最小混合命令接口；在不透明场景之后画一个固定半透明平面，测试仍开启、该平面不写深度，结束后恢复写入和混合状态。
- **边界**：只观察一层透明，不把复杂排序一起做；不新增通用 Material 系统。
- **验收**：alpha 为 0、0.5、1 的受控结果符合手算趋势；透明平面能被前方不透明物体挡住；下一帧清深度正常。
- **易错／追问**：半透明为什么仍常需要深度测试？关闭写入与关闭测试分别会改变什么？

### 第 51 课：两层透明的顺序与最小排序

- **用时／前置**：60～90 分钟；第 50 课的颜色和状态约定明确。
- **目标与讲解**：用两层颜色说明混合的顺序相关性；认识不透明先画、透明随后排序的基本组织方式，以及物体级排序的局限。
- **练习步骤**：固定两个不相交的透明矩形，先预测 A→B 与 B→A；把模型和排序键放入小型 CPU 绘制列表，用 `std::sort` 按约定的相机空间深度排远到近；移动相机复查。
- **边界**：仅解决两个可整体排序的平面；相交／循环遮挡明确记为局限，不扩展 OIT、完整场景或资源管理。
- **验收**：两种顺序的差异可解释；受控场景在相机移动后顺序仍正确；不透明与透明的写入状态交接不影响下一帧。
- **易错／追问**：按世界 z 排序为何会在相机转向后失败？按物体中心排序能解决所有相交透明面吗？
