# J 阶段：Metal 与第三后端验证

[返回逐课索引](README.md) · 第 28～30 月／第 118～130 周

> 状态：全部为待执行教案，开课时依据实际进度和工具支持复核。

## 阶段前置与共同边界

已有真实 OpenGL／OpenGL ES 和 Vulkan 核心场景及其接口取舍记录。准备可开发的 Apple 环境；先以 macOS 小窗口为目标，iOS 移植如有真实需求再另拆课程。

这是验证第三后端的阶段，不是先推倒前两后端重写。先用独立最小入口学清设备、资源、提交、呈现与寿命；再迁入既有接口。Objective-C++／系统桥接的内存管理约定须显式说明，Apple 工具与 SDK 支持开课时核查。

课内按顺序推进，后课以前课的验收成果为前置；每课只完成下列一个核心练习。若环境准备或实现超过 90 分钟，拆课并更新实际课号，不省略验收。所有实现课都须实际读改动并完成与风险相称的构建／运行检查；复盘课如改代码，也须补做行为回归。

## 第一组：语言桥接与设备

### J01：Apple 环境与接入方案

- **用时**：30～60 分钟。
- **讲解**：SDK、目标系统、Metal 设备支持及 Objective-C++／包装层选择。
- **核心练习与边界**：核对本机工具链并评估最小接入路径，新增依赖先确认。
- **验收**：明确目标为 macOS 或另行批准的平台，不把兼容层 Vulkan 当 Metal 原生成果。

### J02：桥接对象与内存管理

- **用时**：45～75 分钟。
- **讲解**：C++ RAII、Objective-C 对象引用、ARC 与临时对象寿命。
- **核心练习与边界**：用一个小桥接对象实验明确跨语言所有权，不接复杂渲染。
- **验收**：能说明谁持有谁、何时释放，普通 C++ 头不扩散平台对象类型。

### J03：Device 与 Command Queue

- **用时**：50～80 分钟。
- **讲解**：设备、命令队列、资源创建入口和错误反馈。
- **核心练习与边界**：创建最小 Metal 设备与队列，并建立项目侧拥有关系。
- **验收**：无设备时可诊断退出，资源包装不成为全局单例。

### J04：平台桥接架构复盘

- **用时**：30～50 分钟。
- **讲解**：Apple 视图、应用流程、设备对象和公共渲染边界。
- **核心练习与边界**：画语言／模块依赖和销毁顺序，检查桥接实现隔离。
- **验收**：非 Apple 目标无需编译平台实现，公共场景不包含 Objective-C 语法。

## 第二组：第一帧呈现

### J05：可呈现表面与 drawable

- **用时**：60～90 分钟。
- **讲解**：Metal 图层／视图、像素尺寸、drawable 获取和可用性。
- **核心练习与边界**：建立最小窗口呈现表面，先检查 drawable 获取与释放。
- **验收**：resize 尺寸来自实际像素，无 drawable 时可安全跳过。

### J06：清屏命令与提交

- **用时**：50～80 分钟。
- **讲解**：render pass 描述、encoder、command buffer 与呈现时机。
- **核心练习与边界**：编码一个颜色清除并呈现，不创建顶点资源。
- **验收**：连续清屏可见，encoder 结束和提交顺序可解释，错误不静默丢失。

### J07：Metal Shader 与 Pipeline

- **用时**：60～90 分钟。
- **讲解**：MSL 函数、库、Pipeline state、附件格式与编译日志。
- **核心练习与边界**：用 Shader 固定顶点画一个三角形，限定单目标输出。
- **验收**：三角形可见，错误 Shader 有日志，Pipeline 格式与目标一致。

### J08：呈现链路架构复盘

- **用时**：30～50 分钟。
- **讲解**：drawable 借用、pass 描述、编码和完成的寿命。
- **核心练习与边界**：对照 Vulkan 首帧路径列出显式与隐式责任差别。
- **验收**：不把 command buffer 提交当执行完成，视图不拥有场景资源库。

## 第三组：网格与纹理

### J09：顶点 Buffer 与布局

- **用时**：50～80 分钟。
- **讲解**：MTLBuffer、字节偏移、顶点描述与 CPU 数据。
- **核心练习与边界**：上传已知三角形顶点，核对格式、stride 与属性位置。
- **验收**：与固定顶点路径一致，非法长度有边界检查，CPU 指针寿命明确。

### J10：静态纹理与 sampler

- **用时**：60～90 分钟。
- **讲解**：texture 描述、像素行步长、上传与采样状态。
- **核心练习与边界**：显示已有非对称小图，先限定一种像素格式和上传路径。
- **验收**：方向／颜色可解释，资源格式得到支持，缺图失败可恢复。

### J11：矩阵参数与索引立方体

- **用时**：60～90 分钟。
- **讲解**：CPU／Shader 数据对齐、索引类型、绑定位置与坐标约定。
- **核心练习与边界**：把既有立方体接入最小矩阵参数缓冲并旋转观察。
- **验收**：索引和变换正确，能说明结构体布局如何验证，不靠碰巧对齐。

### J12：Metal 资源架构复盘

- **用时**：30～50 分钟。
- **讲解**：网格、纹理、参数缓冲和提交引用的所有权。
- **核心练习与边界**：画 CPU MeshData 到 Metal 资源的路径，检查格式转换的归属。
- **验收**：CPU 导入模块继续复用，Metal 类型不进入素材描述。

## 第四组：深度、帧与尺寸

### J13：深度状态与剔除

- **用时**：50～80 分钟。
- **讲解**：深度附件、深度状态对象、清除和正面方向约定。
- **核心练习与边界**：复演已有两个遮挡物实验，校准立方体面朝向。
- **验收**：深度和绕序各自可解释，错误不靠关掉所有测试掩盖。

### J14：在途帧与参数缓冲

- **用时**：60～90 分钟。
- **讲解**：CPU 改写、GPU 读取、帧槽和完成通知。
- **核心练习与边界**：用有界帧槽避免覆盖正在使用的参数，保持同步简单。
- **验收**：运行无闪烁或数据竞争，完成回调访问状态的线程和寿命明确。

### J15：目标尺寸变化

- **用时**：50～80 分钟。
- **讲解**：drawable 尺寸、深度附件重建和旧帧使用结束。
- **核心练习与边界**：resize 时更新投影与尺寸相关资源，处理不可呈现窗口期。
- **验收**：拉伸／最小化恢复无错误，旧附件不在 GPU 使用中提前回收。

### J16：帧生命周期复盘

- **用时**：30～50 分钟。
- **讲解**：CPU 帧号、drawable、参数槽和 GPU 完成的关系。
- **核心练习与边界**：写尺寸变化与在途帧交错的时序，检查等待与释放。
- **验收**：能区分每帧资源与每尺寸资源，回调不借用已销毁 Application。

## 第五组：存储、上传与诊断

### J17：资源存储模式实验

- **用时**：45～75 分钟。
- **讲解**：共享／私有等存储方式、实际设备内存模型与 CPU 可访问性。
- **核心练习与边界**：在当前硬件支持范围比较一个小缓冲的两条创建／更新路径。
- **验收**：支持能力有实测依据，不把某台统一内存设备经验推广到所有 Apple GPU。

### J18：异步上传与回收

- **用时**：60～90 分钟。
- **讲解**：blit 工作、上传中转、提交完成与资源发布。
- **核心练习与边界**：对一张纹理建立有界上传路径，完成条件满足后才发布。
- **验收**：取消不发布半成品，中转资源不提前复用，主线程响应保持可测。

### J19：命令错误与 GPU 诊断

- **用时**：45～75 分钟。
- **讲解**：编码错误、执行失败、调试标签与验证工具。
- **核心练习与边界**：对一个受控错误获取可定位信息，再恢复合法路径。
- **验收**：日志关联具体资源／pass，不忽略 command buffer 的执行结果。

### J20：存储与同步架构复盘

- **用时**：30～50 分钟。
- **讲解**：存储策略、上传队列、资源寿命与平台差异。
- **核心练习与边界**：对照已有 Vulkan 上传设计，记录能复用的概念和不能照搬的细节。
- **验收**：平台特性留在后端实现，公共接口不强迫所有后端采用相同内存策略。

## 第六组：核心场景与工具

### J21：单灯材质核心场景

- **用时**：60～90 分钟。
- **讲解**：MSL 参数映射、材质空间与既有着色约定。
- **核心练习与边界**：迁移一份固定材质模型，只支持已有对照集。
- **验收**：相机与参数操作可用，与前两后端差异有可解释记录。

### J22：两遍离屏预览

- **用时**：60～90 分钟。
- **讲解**：离屏纹理、读写用途、pass 依赖与最终呈现。
- **核心练习与边界**：将已稳定的原样离屏预览迁入 Metal；不在本课新增后处理算法。
- **验收**：目标尺寸／颜色正确，无同一纹理的非法读写重叠。

### J23：Apple GPU 抓帧与测量

- **用时**：45～75 分钟。
- **讲解**：本机抓帧工具、资源检查、CPU／GPU 时间与采样条件。
- **核心练习与边界**：在支持环境定位一个 draw 和一次上传，保存固定场景的基线。
- **验收**：能把画面对应到资源与命令，测量条件完整，未可用指标不编造。

### J24：三后端功能边界复盘

- **用时**：35～60 分钟。
- **讲解**：同一功能的不同实现成本、接口缺口与支持范围。
- **核心练习与边界**：对照 OpenGL／Vulkan／Metal 核心场景，列出当前抽象不合适的具体点。
- **验收**：每个问题对应真实代码和行为，不因第三后端存在就泛化所有接口。

## 第七组：用第三后端修正抽象

### J25：选择一个接口缺口

- **用时**：40～70 分钟。
- **讲解**：抽象泄漏、必要差异、兼容修改与迁移面。
- **核心练习与边界**：从 J24 选一个有证据的问题，写最小接口修改提案。
- **验收**：有前后调用样例、影响文件与回退办法，不一次重写资源系统。

### J26：能力与不支持结果

- **用时**：45～75 分钟。
- **讲解**：能力描述、调用前决策、运行失败与可选功能。
- **核心练习与边界**：为选定接口补一种明确能力／不支持表达，验证三后端映射。
- **验收**：上层可以做合理降级，不能用成功空实现掩盖缺失能力。

### J27：Metal 接入公共切片

- **用时**：60～90 分钟。
- **讲解**：后端适配、资源句柄和公共场景输入。
- **核心练习与边界**：将一个已完成 Metal 模型切片接入修正后的接口，其余迁移另拆。
- **验收**：同一上层场景可选 Metal，平台资源寿命仍可诊断。

### J28：接口迁移架构复盘

- **用时**：35～60 分钟。
- **讲解**：兼容层、临时桥接代码、行为回归与删除时机。
- **核心练习与边界**：审阅一个切片的三后端实现，检查改动是否超出真实需求。
- **验收**：旧后端仍运行，新增接口有实际使用者，临时兼容代码有退出条件。

## 第八组：平台对照与阶段报告

### J29：Apple 与 Android 生命周期对照

- **用时**：40～70 分钟。
- **讲解**：平台表面、可呈现性、资源恢复和后台工作的不同模型。
- **核心练习与边界**：使用已有实测记录比较 macOS Metal 与 Android ES 的恢复路径。
- **验收**：区分已实测平台与未做的 iOS 路径，不把 Metal 套成 OpenGL Context 模型。

### J30：三后端回归矩阵

- **用时**：45～75 分钟。
- **讲解**：功能集、容差、失败／未支持／未验证的区分。
- **核心练习与边界**：对共同核心场景做最小回归，分别记录设备、API 与构建。
- **验收**：每项结论有对应实测，公共接口改动未破坏前两条路径。

### J31：迁移成本与错误抽象报告

- **用时**：45～75 分钟。
- **讲解**：改动范围、调试成本、重复代码与真实差异。
- **核心练习与边界**：用已完成迁移写一份具体取舍报告，记录一个被修正的错误假设。
- **验收**：报告有代码位置和运行证据，不只写“抽象更优雅”。

### J32：Metal 阶段验收与季度复盘

- **用时**：50～80 分钟。
- **讲解**：第三后端的功能、寿命、性能与工程维护证据。
- **核心练习与边界**：审阅矩阵、工具结果和接口报告，选择规模化阶段的真实压力问题。
- **验收**：Metal 核心切片可运行，未迁移模块有范围说明，不宣称全功能三后端一致。
