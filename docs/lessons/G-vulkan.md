# G 阶段：Vulkan 与后端边界

## 阶段前置与共同边界

桌面与 Android／OpenGL ES 最小场景已经验收。先选一个实际可用的 Vulkan 目标，固定 SDK、Shader 编译工具与设备能力；macOS 若经兼容层运行，明确记为兼容层结果。

前半阶段允许在独立 Vulkan 入口逐件建立资源，原 OpenGL 场景保持可运行。每种句柄从首次引入就说明父对象、所有者与销毁顺序；先用清楚的同步，再考虑减少等待。G27 对照场景运行前不提取 RenderDevice，不设计完整引擎或跨所有 API 的统一功能集。

课内按顺序推进，后课以前课的验收成果为前置；每课只完成下列一个核心练习。若环境准备或实现超过 90 分钟，拆课并更新实际课号，不省略验收。所有实现课都须实际读改动并完成与风险相称的构建／运行检查；复盘课如改代码，也须补做行为回归。

## 第一组：启动与对象关系

### G01：Vulkan 目标与工具准备

- **用时**：30～60 分钟。
- **讲解**：显式 API 的责任、驱动／SDK、验证层与设备限制。
- **核心练习与边界**：核对实际平台并评估工具安装，选择最小 API 能力基线后等确认。
- **验收**：原 OpenGL 仍可运行，记录原生或兼容层路径及暂不使用的高级特性。

### G02：Instance 与验证消息

- **用时**：60～90 分钟。
- **讲解**：Instance 扩展、验证层、回调生命周期与诊断级别。
- **核心练习与边界**：在已就绪环境创建最小 Instance 与诊断回调，配套 RAII 释放。
- **验收**：启动退出无未处理验证错误，能说明回调用户数据活多久。

### G03：设备与队列选择

- **用时**：60～90 分钟。
- **讲解**：物理／逻辑设备、队列族、呈现支持和能力筛选。
- **核心练习与边界**：建立一个窗口 Surface，选择满足当前需求的设备与队列组合。
- **验收**：输出选择依据，缺能力明确失败，Surface／Device 父对象寿命正确。

### G04：Vulkan 启动架构复盘

- **用时**：30～50 分钟。
- **讲解**：平台 Surface、设备资源与应用流程的依赖。
- **核心练习与边界**：画启动失败回滚图，逐项核对父对象先创建后销毁的关系。
- **验收**：失败在任一步都可安全退出，没有引入全局万能设备单例。

## 第二组：目标与命令

### G05：Swapchain 与图像视图

- **用时**：60～90 分钟。
- **讲解**：表面格式、extent、呈现模式、交换链图像的所有权。
- **核心练习与边界**：创建最小交换链及视图，先不提交绘制。
- **验收**：参数来自实际能力，视图自行销毁而交换链图像不被当自建图像释放。

### G06：最小颜色渲染目标

- **用时**：60～90 分钟。
- **讲解**：附件、加载／存储行为、RenderPass 与 framebuffer。
- **核心练习与边界**：为交换链图像建立一种传统 RenderPass 路径，先只计划清颜色。
- **验收**：对象创建成功，格式匹配；不同时实现动态渲染两套路径。

### G07：录制一段清屏命令

- **用时**：50～80 分钟。
- **讲解**：命令池、命令缓冲状态、开始／结束与复用条件。
- **核心练习与边界**：录制一次颜色清除，保持命令与 framebuffer 的寿命明确。
- **验收**：命令录制通过验证，能说明录制不等于已经执行或呈现。

### G08：交换链与命令架构复盘

- **用时**：30～50 分钟。
- **讲解**：交换链相关资源、可重建资源与设备级资源的分层。
- **核心练习与边界**：画一帧所需对象关系并检查失败释放顺序。
- **验收**：能区分自己分配的对象与借用的交换链图像，不把尺寸资源放进全局。

## 第三组：第一帧与三角形

### G09：获取、提交、呈现与同步

- **用时**：60～90 分钟。
- **讲解**：acquire、semaphore、fence、队列提交及 CPU 等待。
- **核心练习与边界**：用最保守的一帧在途方案呈现清屏画面。
- **验收**：连续运行与退出通过验证，能解释每个等待防止哪种提前使用。

### G10：固定图形 Pipeline

- **用时**：60～90 分钟。
- **讲解**：预编译 Shader、Pipeline layout 与固定功能状态。
- **核心练习与边界**：用 Shader 内少量固定顶点显示三角形，先不上传网格。
- **验收**：画面正确，Shader 和验证错误可定位，不复制完整材质系统。

### G11：可映射顶点缓冲

- **用时**：60～90 分钟。
- **讲解**：buffer、内存需求、内存类型与可见性。
- **核心练习与边界**：上传一个小三角形顶点数组，按实际内存性质处理写入可见性。
- **验收**：GPU 正确读取顶点，能解释 host visible 与 coherent 的区别。

### G12：首条绘制链路复盘

- **用时**：30～50 分钟。
- **讲解**：CPU 写数据、命令引用、GPU 执行与释放的时序。
- **核心练习与边界**：对照 OpenGL 画出新增的显式责任，检查每帧是否盲目重建资源。
- **验收**：能从数组追踪到三角形，首帧和退出均无未处理验证问题。

## 第四组：资源与上传基础

### G13：资源失败回滚与移动语义

- **用时**：45～75 分钟。
- **讲解**：Vulkan 子资源拥有关系、move-only 和部分初始化。
- **核心练习与边界**：对现有一个 buffer 包装做创建失败与移动后的释放检查。
- **验收**：不重复释放，不留下绑定内存，目标已有资源时的赋值语义清楚。

### G14：uniform 与描述符

- **用时**：60～90 分钟。
- **讲解**：descriptor layout／pool／set、绑定与数据寿命。
- **核心练习与边界**：给三角形加入一个矩阵 uniform，仍保持一帧在途。
- **验收**：改矩阵可见，布局与 Shader 匹配，更新时机不会覆盖 GPU 正在读的数据。

### G15：staging buffer 复制

- **用时**：60～90 分钟。
- **讲解**：上传中转、设备本地资源、复制命令与完成条件。
- **核心练习与边界**：将小顶点数据从 staging 复制到目标 buffer，完成后再释放中转资源。
- **验收**：与直接映射路径画面一致，能说明 staging 为什么不能提交后立即销毁。

### G16：描述符与上传架构复盘

- **用时**：30～50 分钟。
- **讲解**：数据绑定与资源所有权不同，命令中的借用期限。
- **核心练习与边界**：记录 uniform、descriptor 与 staging 的时间线，定位一例提前释放风险。
- **验收**：原始句柄暴露受限，资源包装不自行控制窗口或应用循环。

## 第五组：纹理与深度

### G17：纹理图像与复制转换

- **用时**：60～90 分钟。
- **讲解**：image、内存、子资源布局、访问阶段与 barrier。
- **核心练习与边界**：把一张已解码小图复制到纹理图像并完成所需布局转换，暂不采样。
- **验收**：验证层无未处理布局／访问问题，能说明每次转换服务于哪一步。

### G18：纹理视图与采样描述符

- **用时**：60～90 分钟。
- **讲解**：image view、sampler、采样描述符与 Shader 绑定。
- **核心练习与边界**：在 G17 资源上显示受控纹理矩形，暂不生成 Mipmap。
- **验收**：非对称图方向正确，描述符引用的所有资源活到 GPU 使用结束。

### G19：深度附件与遮挡

- **用时**：60～90 分钟。
- **讲解**：支持格式、深度清除／测试／写入与渲染目标配置。
- **核心练习与边界**：为现有目标增加一个深度附件，用两个矩形复演遮挡实验。
- **验收**：绘制顺序对正常遮挡无影响，深度目标尺寸和释放顺序正确。

### G20：图像与多资源复盘

- **用时**：30～50 分钟。
- **讲解**：图像状态、附件用途、采样用途与 CPU 对象寿命。
- **核心练习与边界**：为纹理和深度图各画一条使用时间线，审查 barrier 与绑定边界。
- **验收**：能区分布局转换与内存分配，不用全局等待掩盖所有未知同步问题。

## 第六组：多帧与重建

### G21：两帧在途与帧资源

- **用时**：60～90 分钟。
- **讲解**：帧槽、交换链图像索引、fence 复用与独立数据。
- **核心练习与边界**：把已有一帧方案扩到两帧，为会被改写的数据建立帧槽。
- **验收**：不混用帧号和图像号，验证通过，CPU 不覆盖仍在使用的 uniform。

### G22：尺寸变化与交换链重建

- **用时**：60～90 分钟。
- **讲解**：out-of-date、suboptimal、零尺寸与相关资源依赖。
- **核心练习与边界**：处理窗口尺寸变化，先采用明确等待后重建的简单安全路径。
- **验收**：resize／最小化恢复成功，旧视图与附件释放完整，失败可诊断。

### G23：上传完成与资源发布

- **用时**：60～90 分钟。
- **讲解**：同队列顺序、可见性、上传批次与使用前依赖。
- **核心练习与边界**：将一次上传接入正常帧循环，以明确完成条件发布资源；暂不加专用队列。
- **验收**：资源未就绪时使用占位或等待策略，完成后正确显示，无提前回收。

### G24：同步与恢复架构复盘

- **用时**：35～60 分钟。
- **讲解**：帧资源、图像资源、重建代次与错误恢复的交叉关系。
- **核心练习与边界**：整理提交／呈现／重建时序，逐个解释现有等待的必要性。
- **验收**：不存在无法说明用途的 barrier／wait，新增复杂同步需有证据。

## 第七组：真实核心场景对照

### G25：矩阵、裁剪与绕序约定

- **用时**：50～80 分钟。
- **讲解**：不同 API 的裁剪深度、屏幕方向与正面约定。
- **核心练习与边界**：用已知坐标点校准相机和投影，迁移纹理立方体。
- **验收**：点位、遮挡和面朝向可预测，修正集中在后端边界而非散改素材。

### G26：固定材质核心场景

- **用时**：60～90 分钟。
- **讲解**：现有材质数据到 Pipeline／descriptor 的映射。
- **核心练习与边界**：迁移一份已稳定的单灯材质模型，限定特性集合。
- **验收**：能旋转观察与切换参数，记录暂不支持的阴影／动画等特性。

### G27：OpenGL 与 Vulkan 对照

- **用时**：45～75 分钟。
- **讲解**：功能一致性、浮点差异、输出容差和同条件测量。
- **核心练习与边界**：用同一受控场景记录两后端画面、资源与一帧数据流。
- **验收**：两条真实路径均能运行，差异有解释；不把视觉接近当像素级证明。

### G28：抽象前架构复盘与评估

- **用时**：35～60 分钟。
- **讲解**：共同需求、真实差异、最小接口与泄漏抽象。
- **核心练习与边界**：从已运行场景提取必要操作清单，写一页 RenderDevice 候选接口与取舍。
- **验收**：每个接口都对应现有调用，不能容纳的差异明确保留在后端。

## 第八组：最小后端接口与 v0.9

### G29：后端契约与资源句柄

- **用时**：45～75 分钟。
- **讲解**：能力查询、句柄寿命、创建失败与提交语义。
- **核心练习与边界**：明确一个最小资源／绘制契约及不支持行为，先检查调用方可表达性。
- **验收**：不暴露 Vk／GL 类型给场景层，不承诺两后端并不存在的统一能力。

### G30：OpenGL 适配一个切片

- **用时**：60～90 分钟。
- **讲解**：组合适配、接口边界、逐步迁移与旧路径对照。
- **核心练习与边界**：只把 G29 的纹理模型切片接入 OpenGL 后端；大范围迁移另拆课。
- **验收**：原场景行为一致，窗口与 Context 所有权不被新接口吞并。

### G31：Vulkan 适配同一切片

- **用时**：60～90 分钟。
- **讲解**：显式同步差异、后端实现细节与共同场景输入。
- **核心练习与边界**：让同一上层场景通过已定义契约运行 Vulkan，保留后端特有资源策略。
- **验收**：两后端可选择运行，生命周期和错误信息仍可诊断；未完成迁移不冒称通用引擎。

### G32：v0.9 验收与季度复盘

- **用时**：50～80 分钟。
- **讲解**：双后端功能、接口成本、迁移风险与后续资产链路。
- **核心练习与边界**：汇总真实对照、验证层记录、接口取舍和剩余切片。
- **验收**：核心场景跨后端通过，接口有实证依据；未完成切片补课后再进入 H。
