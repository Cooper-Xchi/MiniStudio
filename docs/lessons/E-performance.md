# E 阶段：测量、优化与回归

[返回逐课索引](README.md) · 第 13～15 月／第 53～65 周

> 状态：全部为待执行教案，开课时依据实际进度和工具支持复核。

## 阶段前置与共同边界

D 阶段可交互、异步加载与动画场景已稳定。先固定硬件、构建配置、分辨率、场景、相机与播放时间；计时结果必须注明垂直同步、预热和采样区间。

优化课先复用已完成的场景，不同时增加新效果。工具按实际主机与 API 支持选择，开课时检查官方资料；不把 macOS 上不可用的抓帧工具写成已验证路径。只有数据能证明问题时才保留优化，画面、内存和复杂度代价同时记录。

课内按顺序推进，后课以前课的验收成果为前置；每课只完成下列一个核心练习。若环境准备或实现超过 90 分钟，拆课并更新实际课号，不省略验收。所有实现课都须实际读改动并完成与风险相称的构建／运行检查；复盘课如改代码，也须补做行为回归。

## 第一组：可靠的基线

### E01：测量问题与实验条件

- **用时**：30～55 分钟。
- **讲解**：帧时间与 FPS、CPU／GPU／等待的区别、可比较条件。
- **核心练习与边界**：为已有场景写一页测量协议，定义一个具体问题与固定操作。
- **验收**：条件、指标和噪声来源明确，不把肉眼流畅当作数据。

### E02：帧时间样本与分位数

- **用时**：45～75 分钟。
- **讲解**：单调时钟、预热、样本分布、均值与尾部延迟。
- **核心练习与边界**：记录有限数量帧时间并输出中位数与高分位数。
- **验收**：样本可重算，暂停和加载区间有标记，不只报告平均 FPS。

### E03：CPU 分段计时

- **用时**：45～75 分钟。
- **讲解**：作用域计时、嵌套范围、记录开销与归因边界。
- **核心练习与边界**：对事件、更新、准备绘制和提交分段计时，使用有界记录存储。
- **验收**：能找出一个具体耗时段，计时自身成本有估计。

### E04：测量代码架构复盘

- **用时**：30～50 分钟。
- **讲解**：诊断接口、业务代码侵入和 Release 开销。
- **核心练习与边界**：检查计时开关、样本寿命及输出责任，绘制指标来源表。
- **验收**：关闭诊断不改变业务行为，没有每帧无限增长的日志容器。

## 第二组：CPU／GPU 诊断工具

### E05：本机性能工具与能力核对

- **用时**：30～60 分钟。
- **讲解**：采样器、GPU 抓帧、内存工具能回答的不同问题。
- **核心练习与边界**：核对当前平台工具支持及安装成本，选择一条可行路径并等必要确认。
- **验收**：形成工具／平台／API 能力表，未可用工具有替代观测方案。

### E06：读取一帧 GPU 工作

- **用时**：45～75 分钟。
- **讲解**：draw call、绑定资源、渲染目标与事件顺序。
- **核心练习与边界**：用可用工具检查一个固定帧；不支持抓帧时先记录命令与状态。
- **验收**：能把至少一个屏幕物体对应到绘制事件，局限如实标注。

### E07：加载时间线

- **用时**：45～75 分钟。
- **讲解**：请求、读取、解码、排队、上传和可见时间。
- **核心练习与边界**：为一份资源记录跨线程阶段时间，关联同一任务 ID。
- **验收**：说明等待和实际工作分别占多少，时钟基准一致。

### E08：瓶颈假设复盘

- **用时**：30～50 分钟。
- **讲解**：相关性与因果、测量盲点、一次改变一个变量。
- **核心练习与边界**：根据当前数据写两个可检验假设并选择先验证的一项。
- **验收**：每个假设含预测与否定条件，不能只写“优化渲染”。

## 第三组：提交与状态成本

### E09：可重复压力场景

- **用时**：45～75 分钟。
- **讲解**：固定种子、对象数量、相机路径与配置参数。
- **核心练习与边界**：用已有资源生成可调数量的实例，保存测试配置。
- **验收**：同配置可复现同场景，规模和硬件条件在结果中可追踪。

### E10：绘制与状态计数

- **用时**：45～70 分钟。
- **讲解**：draw 数量、状态设置次数和 GPU 工作量不等价。
- **核心练习与边界**：给已有提交路径加有界计数，改变对象数量观察增长。
- **验收**：计数与场景规模一致，能说明计数不能直接替代耗时。

### E11：不透明绘制排序实验

- **用时**：50～80 分钟。
- **讲解**：排序复杂度、材质分组、状态复用与透明限制。
- **核心练习与边界**：只重排不透明列表以减少切换，对照 CPU 时间和调用数。
- **验收**：画面不变、数据可比较；若排序更慢，记录结论并保留简单方案。

### E12：绘制列表架构复盘

- **用时**：30～50 分钟。
- **讲解**：准备数据、排序策略、提交和资源引用的寿命。
- **核心练习与边界**：审查绘制列表是否持有失效引用，并归档本轮假设结果。
- **验收**：透明顺序规则未被破坏，优化没有扩散到窗口或资源解析模块。

## 第四组：重复几何与 GPU 时间

### E13：批处理的可行性分析

- **用时**：35～60 分钟。
- **讲解**：共享状态、合并边界、顶点复制与额外内存。
- **核心练习与边界**：选一组静态 Sprite，手算可减少的提交及新增数据量。
- **验收**：能说明哪些对象不可合批；形成实现或放弃的依据。

### E14：最小实例化绘制

- **用时**：60～90 分钟。
- **讲解**：每顶点／每实例属性、实例数据生命周期和更新成本。
- **核心练习与边界**：对重复立方体做一条受控实例化路径，保持原路径可对照。
- **验收**：位置与材质限制明确，提交减少，记录 CPU 时间和内存变化。

### E15：GPU 时间查询

- **用时**：50～80 分钟。
- **讲解**：GPU 异步执行、查询结果延迟和阻塞读回。
- **核心练习与边界**：在支持的环境对一个 pass 计时，延迟消费结果而非立即等待。
- **验收**：数据带支持／有效性信息，不把 CPU 提交时间误称 GPU 时间。

### E16：实例化收益与结构复盘

- **用时**：35～60 分钟。
- **讲解**：CPU 节省、GPU 工作与维护成本的联合判断。
- **核心练习与边界**：比较原路径和实例化数据，检查实例缓冲所有权和容量策略。
- **验收**：得出有条件的结论；收益不足时说明原因，不为报告制造提升。

## 第五组：可见性与计算复杂度

### E17：包围体与空间约定

- **用时**：45～75 分钟。
- **讲解**：AABB、局部／世界空间、变换后范围与保守性。
- **核心练习与边界**：为已有网格计算包围盒并可视化，先不剔除。
- **验收**：包围盒覆盖变换后的几何，空网格和非均匀缩放有处理。

### E18：最小视锥剔除

- **用时**：60～90 分钟。
- **讲解**：平面测试、保守判定、边界与误剔除风险。
- **核心练习与边界**：用已经验证的包围体剔除明显不可见的不透明实例。
- **验收**：视锥边缘移动无物体跳失，开关剔除画面一致。

### E19：剔除成本与收益

- **用时**：45～75 分钟。
- **讲解**：O(n) 遍历、可见比例、准备时间与 GPU 节省。
- **核心练习与边界**：对高／低可见比例各采样，比较剔除前后时间和数量。
- **验收**：数据说明适用规模，不能用只看不见物体的场景夸大收益。

### E20：空间与绘制依赖复盘

- **用时**：30～50 分钟。
- **讲解**：网格包围体、实例变换、相机与绘制候选集。
- **核心练习与边界**：检查包围体更新时机和失效传播，记录算法与布局取舍。
- **验收**：剔除代码可用 CPU 输入验证，不依赖窗口句柄或具体绘制命令。

## 第六组：内存与上传峰值

### E21：资源内存账本

- **用时**：45～75 分钟。
- **讲解**：CPU 解码内存、缓存、GPU 估算与驱动实际占用的区别。
- **核心练习与边界**：对一条加载路径记录持有字节和释放时机，标明估算项。
- **验收**：能解释峰值同时存在的多份数据，不把所有缓存都叫泄漏。

### E22：容器增长与重复分配

- **用时**：45～75 分钟。
- **讲解**：capacity、reserve、扩容失效与预分配代价。
- **核心练习与边界**：用数据定位一个频繁扩容容器，再实施最小容量策略。
- **验收**：分配次数变化可测、峰值可接受，未全局盲目 reserve 巨量空间。

### E23：分段上传实验

- **用时**：60～90 分钟。
- **讲解**：上传粒度、每帧预算、部分资源不可见状态。
- **核心练习与边界**：对一类大资源分段上传，完成前不发布可绘制句柄。
- **验收**：尾部帧时间与总就绪时间都有记录，取消可释放中间状态。

### E24：峰值内存与异步架构复盘

- **用时**：30～50 分钟。
- **讲解**：队列容量、在途资源、反压与主线程发布。
- **核心练习与边界**：用资源账本检查无限排队可能性，写出一个容量不变量。
- **验收**：峰值来源可解释，预算策略不会造成死锁或永久半加载资源。

## 第七组：压力与回归

### E25：压力输入与失败条件

- **用时**：40～70 分钟。
- **讲解**：大量资源、损坏文件、重复取消与退出的组合风险。
- **核心练习与边界**：建立有限规模的可重放压力脚本或操作序列，先固定一种场景。
- **验收**：有停止条件、种子和资源上限，失败可重复而非随机口述。

### E26：修复一个测得的容量问题

- **用时**：50～80 分钟。
- **讲解**：反压、拒绝／等待／降级策略及响应时间。
- **核心练习与边界**：依据 E25 的真实问题修复一项队列或资源上限行为。
- **验收**：同一序列恢复可控；若未发现问题，则验证现有边界，不虚构缺陷。

### E27：性能回归对照

- **用时**：45～75 分钟。
- **讲解**：相同条件、重复采样、阈值与环境波动。
- **核心练习与边界**：保存小型基线，对一个已完成优化建立可重复比较流程。
- **验收**：结果附波动说明，机器变化不会直接判定成代码回归。

### E28：诊断与测试架构复盘

- **用时**：30～50 分钟。
- **讲解**：产品代码、压力入口、测量输出和测试替身边界。
- **核心练习与边界**：检查测试入口不会进入普通用户流程，归档失败最小样本。
- **验收**：回归可独立执行，日志和样本有界，诊断不反向控制业务状态。

## 第八组：两份优化报告与 v0.8

### E29：第一份优化报告

- **用时**：40～70 分钟。
- **讲解**：问题、假设、方法、数据、结果和副作用的证据链。
- **核心练习与边界**：用已完成的提交／实例化或其他实测优化写一份报告。
- **验收**：原始数据能复算结论，注明平台与构建，截图之外有数值证据。

### E30：第二份优化报告

- **用时**：40～70 分钟。
- **讲解**：不同瓶颈的证据独立性、失败实验的价值。
- **核心练习与边界**：选择另一项已有有效优化整理报告；不足则安排补充测量课。
- **验收**：两份报告不是同一变化换标题，未达到收益时不标记阶段通过。

### E31：诊断演练与作品说明

- **用时**：45～75 分钟。
- **讲解**：从症状到假设、采样到定位、修复到回归的叙述。
- **核心练习与边界**：复演一个已有卡顿／内存故障，录制或写成可复现说明。
- **验收**：能回答为什么选这个工具、排除了什么，保护设备和路径敏感信息。

### E32：v0.8 与季度架构复盘

- **用时**：45～75 分钟。
- **讲解**：性能收益、复杂度、稳定性和移动端准备度。
- **核心练习与边界**：审阅两份报告、压力结果和所有权图，确定 Android 最小移植场景。
- **验收**：两项优化有实测证据，未完成项明确补课；不把桌面性能推断成真机结果。
